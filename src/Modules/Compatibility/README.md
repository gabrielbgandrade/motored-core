# Module: Compatibility

## Purpose
Motorcycle-to-tire compatibility engine and Mi Garage experience without linking motorcycles inside products. Motorcycles map to canonical tire sizes (`motored_compat_*`), products expose native WooCommerce tire attributes synced into a lightweight index (`motored_compat_product_index`), and page-cache-safe client-side hydration evaluates compatibility from `<span hidden data-motored-fit>` markers.

## Public contracts
- `SizeParser::parse( string $raw )`, `SizeParser::format_full_size()` (pure canonicalizer preserving imperial trailing zeroes as strings).
- `TireSpecs::speed_rank()`, `TireSpecs::load_kg()`, `TireSpecs::format_load_speed()`, `TireSpecs::attribute_order_map()`, `TireSpecs::normalize_position()`, `TireSpecs::normalize_construction()`.
- `MatchEngine::evaluate_product()`, `MatchEngine::bike_profile()`, `MatchEngine::matching_product_ids()`, `MatchEngine::compatible_motos_for_product()`.
- Shortcode `[motored_compat_selector mode="shop|garage"]`.
- REST namespace `motored/v1`: public `/compat/brands`, `/compat/brands/{brand_id}/models` (plus legacy `/compat/models?brand_id=`), `/compat/models/{model_id}/years` (plus legacy `/compat/years?model_id=`), `/compat/bike/{slug}`, `/compat/product/{id}/motos`; authenticated `/garage`, `/garage/{slug}`.
- My Account endpoint `mi-garage`.

## Data model
- Option `motored_compatibility` (`autoload = false`): `enabled`, `max_garage_bikes`, `strict_specs`, `show_incompatible_badge`, `garage_cta`, `oem_first_sort`, `analytics_events`, `rename_tech_tab`, `show_compat_tab`, `auto_fill_dimensions`, `disclaimer`, `shop_url`.
- Option `motored_compat_rewrite_ver` (`autoload = false`), `motored_compat_last_import`, `motored_compat_import_job_<id>` (temporary batch staging).
- Tables (`Migration 2026112001`, updated `2026112201` for `notes text DEFAULT NULL`): `motored_compat_brands`, `motored_compat_models`, `motored_compat_versions` (`year_to = 0` sentinel for present, immutable `slug`), `motored_compat_sizes`, `motored_compat_fitments`, `motored_compat_equivalences`, `motored_compat_product_index` (`product_id` PK, no `variation_id`).
- Meta keys: `_motored_garage` (`user_meta`), `_motored_full_size` (`product` post meta).
- Cache buckets (`CompatCache`, persistent object cache only): `compat_catalog` (TTL 6h), `compat_matches` (TTL 1h). Never writes transients to `wp_options` when Redis is inactive.

## Configuration keys
Edited in **WooCommerce > Ajustes > Motored > Compatibilidad** (`enabled` default `no`; `max_garage_bikes` `5`; `strict_specs` `no`; `show_incompatible_badge` `yes` (catalog cards only; the product page always tells the truth about the active bike); `garage_cta` `yes` ("View only tires that fit it" on catalog pages); `oem_first_sort` `yes` (`?moto=` results OEM → alternative → equivalent when the shopper did not pick a sorting); `analytics_events` `no` (anonymous `window.dataLayer` events); `rename_tech_tab` `yes`; `show_compat_tab` `yes`; `auto_fill_dimensions` `no`; `disclaimer` empty -> translated default; `shop_url` empty -> WC shop URL). No secrets.

## Main flows
1. **Product sync (ERP-safe):** Product save or `set_object_terms` on our 6 indexed taxonomies -> `ProductIndexSync::mark_dirty()` -> `shutdown` (<= 20) or AS `motored_compat_reindex` (> 20) computes MD5 `terms_hash` -> exits early if unchanged (ERP price/stock saves write 0 rows); otherwise updates `motored_compat_product_index` and optionally fills empty `ancho`/`perfil`/`rodado` on single tires (`never` on kits).
2. **Matching (`MatchEngine`):** `bike_profile( slug )` loads direct `oem`/`alt` fitments + 1-hop directed equivalences originating ONLY from `oem` fitments (non-transitive). Kits match iff BOTH front and rear axles pass.
3. **Storefront (cache-safe):** Public HTML is identical for all visitors (`<span hidden data-motored-fit>`), `the_posts` primes loop products in 1 SQL query, `compat-garage.js` evaluates badges client-side from `localStorage` (0 REST requests when browsing, 12h TTL revalidation), product pages include an inline lazy compatibility checker (`compat-selector.js` in `check` mode) plus fixed-order Technical information rows (`Brand -> Model -> Full size -> Position -> Index -> Tube -> Construction -> Usage`), and `compat-tab.js` lazy-loads compatible bikes via `IntersectionObserver` only when the Compatibility tab opens.
4. **Base catalog prefill (Argentina):** In **WC > Ajustes > Motored > Compatibilidad** (step **"2. Load base catalog (Argentina)"**, one click, no confirmation screen) or in **Productos > Compatibilidad > Import / Export**, loads bundled `data/compat-base-ar.json`, imports synchronously (`ImportRunner::start(..., ['sync' => true])`) into `motored_compat_*` tables (optionally forcing all versions to `draft`). Data must be reviewed against local manuals/VIN before publishing.
5. **Natural admin workflow (`Productos > Compatibilidad`):** Defaults to **Motorcycles** (`versions`) with an overview/setup box, 1-step **Quick add motorcycle** (Brand + Model + Years + Front/Rear OEM sizes with `<datalist>` autocomplete), Brand/Status/Verified/Alias filters, inline tire sizes per row, bulk Publish/Verify/Draft/Delete actions, live **Store matching preview** on version edit, Brand/Model edit forms, 1-click equivalence Approve/Pause + same-rim guard, and compatibility + catalog filter index statuses inside WooCommerce product edit screens (alongside the optional `_motored_full_size` display override).

## Performance and security notes
- `register()` executes 0 DB queries and enqueues 0 scripts. Readable (not hand-minified) sources: `compat-garage.js` (~15 KB raw, ~4.5 KB gzip) only on WC shop/archive/product/account pages when enabled; `motored-ui.js` (shared cascade/text/events, ~9 KB) + `compat-selector.js` (~3 KB) only with a selector/banner; `compat-tab.js` (~5 KB) only inside the Compatibility tab; `compat-garage-page.js` (~5 KB) only on `mi-garage`. CSS: `compat.css` (~12 KB, tokens + Compatibility components) on product/catalog pages with our markup; `catalog-filters.css` only with search/filters.
- `ev()` in `compat-garage.js` mirrors `MatchEngine::evaluate_product()`; both are checked against `tests/fixtures/compat-cases.json` (`FrontendFixesTest` + `node tests/js/compat-parity.test.js`). Change both together.
- `?moto=` result IDs are cached best fit first (OEM → alternative → equivalent; cache key `mids2_`), so `orderby=post__in` gives the relevance order with no extra query.
- Admin screens check `manage_woocommerce` + nonces and use `Admin\Ui` / `motored-admin.css` exclusively. All SQL uses `$wpdb->prepare()` with `Db::table()`. Authenticated garage REST routes verify `is_user_logged_in()` + `wp_rest` nonce.

## Known limitations
- Supports simple products only (including simple-product kits/combos; variable products are out of scope per store catalog decision).
- JSON import only (no CSV).
- `pa_*` global attributes and terms are preserved on uninstall so WooCommerce product catalogs remain intact.
